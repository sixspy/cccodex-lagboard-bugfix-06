# 冻写切断卡

- 卡片编号：FWC-06-01
- 钉死日期：2026-11-19（冻结当天）
- 适用范围：冻结徽标仍亮、却仍有冻结源报文进入到达入库的情形
- 入口：沿用「时限台 → 到达登记」菜单，不另建冻写台
- 会话：沿用冻写侧既有登录会话（`/api/login` 签发的 Bearer）
- 落盘：库文件挂冻写专卷（compose 卷 `lagboard-freeze-data:/app/data`）

## 一、切断口径（只能二选一，甲乙不得混用）

本仓钉死 **甲路径**，乙路径作废、不得并行启用：

| 路径 | 口径 | 本仓状态 |
|------|------|----------|
| 甲 | 冻结源入库整笔锁行拒插，记审计，正式到达零增 | **已钉死，唯一生效** |
| 乙 | 先落冻写草稿，按版本戳复检失败则作废草稿，正式到达零新增 | 作废，禁止启用 |

一旦启用乙路径（新增草稿表、草稿接口、草稿回填）即视为偏离本卡。

## 二、冻结源入库的硬约束

1. 冻结徽标仍在时，冻结源任何到达报文一律不落正式流水（`arrivals` 零新增）。
2. 拒写必须留审计（`freeze_audit.action = 拒写`），返回 `423`、`code = FREEZE_REFUSED`、`inserted = false`。
3. 禁止只改入库提示：提示措辞变化不算切断，必须有拒写与零增证据。
4. 调度席与采集席同时打冻结源入库，须先占冻写锁；后交不落库，只记 `冻写争用`（`code = FREEZE_CONTENTION`）。
5. 拒写与争用须在五处同拒一致体现：
   - 源目录牌（`/api/sources` 的 `output_mode` 仍为冻结）
   - 到达卡片（`/api/arrivals` 零新增）
   - 审计列表（`/api/freeze-audit`）
   - 任务附页（`/api/tasks` 的 `freeze_cut = true`、`ingest_allowed = false`）
   - 水位读数（`/api/watermark` 的 `arrivals` 不涨，`freeze_refused` / `freeze_contention` 计数）

## 三、失败测先行（不得越过）

1. 先把「冻结仍入库」复现出来（`scripts/repro_freeze_ingest.py`）。
2. 落拒写失败测：插入成功即红。
3. 再确认双席抢入失败测：缺冻写争用留痕即红。
4. 两条红测齐备后才可改冻写落库；未见插入就改提示不算过关。
5. 测红后改落库，全绿即五处同拒。

## 四、封档与改口

- 本卡钉死后写入冻写切断卡并封档：`docs/freeze-cut-card.封档.json` 记录本文件 `sha256`。
- 冻结当天不许改口切断专册：改本卡正文即令封档哈希失配，测试转红。
- 偏离本卡（改口径、并甲乙、只改提示、绕过冻写锁、缺争用留痕）一律驳回，并在审计列表留 `冻写偏了`。

## 五、修复后行为（验收口径）

- 冻结源入库：`423 FREEZE_REFUSED`，`arrivals` 零增，审计 +1 拒写。
- 双席抢入：先到者 `423 FREEZE_REFUSED`，后交者 `423 FREEZE_CONTENTION`，审计各留一条。
- 非冻结源采集入库：照常 `200`，`inserted = true`。
- 补齐解冻后：同一源恢复入库，`output_mode` 回到可写。
